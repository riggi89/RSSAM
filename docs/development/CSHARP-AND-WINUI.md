# C# and WinUI guidelines

## Language and framework

RSSAM uses C# with nullable reference types and implicit global usings enabled. Production projects target .NET 10 for Windows. Prefer current language features when they improve clarity without obscuring native interop behavior.

## Namespace rules

Use `Microsoft.UI.*` for WinUI types, including colors, brushes, controls and text formatting. Use Windows namespaces only for platform APIs that remain outside WinUI, such as storage, system integration or graphics structures.

Examples:

```csharp
var foreground = Microsoft.UI.Colors.Black;
var overlay = Microsoft.UI.ColorHelper.FromArgb(20, 0, 0, 0);
```

Do not introduce `Windows.UI.Xaml` or other UWP presentation namespaces into the WinUI application.

## Layer boundaries

- Put window and control behavior in `RSSAM.App`.
- Keep Card Idler UI and SteamKit2 behavior inside `RSSAM.CardIdler` so its assembly boundary remains explicit.
- Put reusable models, validation, storage and orchestration in `RSSAM.Core`.
- Put native vtable and Steam interface work in `RSSAM.API`.
- Keep Core free of WinUI controls, brushes, dispatchers and XAML types.
- Access Steam through Core services instead of calling API wrappers from pages.

## WinUI pages and shell integration

Pages that participate in the main shell implement `IShellContentPage`. They should publish state through that contract and raise `ShellStateChanged` when toolbar items, busy state, search state or back-navigation state changes.

Feature-module pages such as `CardIdlerPage` may be navigated directly when they do not use global search or shell toolbar actions. They must expose a public parameterless constructor for `Frame.Navigate`, use application theme resources and provide an explicit localization refresh hook.

Use the shared shell toolbar instead of adding a page-local command bar. Toolbar commands should provide:

- a stable key;
- localized text used by tooltips and accessibility;
- a Segoe Fluent Icons glyph;
- enabled and checked state;
- left or right placement;
- an action or toggle callback.

Use separators only between meaningful action groups. Keep the primary save action first and reload actions on the right where the current page follows that pattern.

## XAML and resources

- Prefer theme resources from `Resources/Styles` over hard-coded colors.
- Keep controls usable in light, dark and high-contrast environments.
- Use shared styles for toolbar buttons, cards, dialogs and InfoBars.
- Use `UseLayoutRounding` where fractional scaling can blur text or borders.
- Avoid fixed widths for user-facing text unless trimming and a tooltip are provided.
- Give icon-only controls localized tooltips and automation names.

When adding a named XAML control, ensure its code-behind reference is generated by the same `x:Class` and do not duplicate names across scopes.

## Title bar and native caption buttons

RSSAM extends content into the Windows title bar. Interactive elements must be included in the non-client passthrough calculation so they receive pointer input instead of dragging the window.

Whenever the app theme changes, synchronize all native caption states:

- active and inactive foreground;
- normal and inactive background;
- hover foreground and background;
- pressed foreground and background.

Test minimize, maximize and close in both themes. A correct normal state does not guarantee correct hover or pressed rendering.

## Async and UI-thread work

- Keep file access, process inspection and Steam worker waits away from the UI thread.
- Use the page busy state for the shell loading bar.
- Marshal final control updates through the page dispatcher when the continuation can run off-thread.
- Never block with `.Wait()` or `.Result` in WinUI event handlers.
- Dispose game services when leaving a selected game.

## Dialogs and notifications

Use `DialogService` for all `ContentDialog` requests so only one dialog is active for the current `XamlRoot`. Use the global InfoBar service for user-initiated completion and errors. Use status text for ongoing or automatic background work.

## Localization

Do not hard-code user-facing text in C# or XAML when it belongs in the interface dictionaries. Add the same key to every JSON file under `RSSAM.Core/Localization/Resources`.

Preserve composite format placeholders exactly. For example, translations of `{0} games loaded` must retain `{0}`. Add the language to normalization, settings validation, the Settings ComboBox and Steam-language mapping when introducing a new culture.

The changelog is intentionally English-only.

## Persistence

Settings and favorites are written atomically. New persistent settings require:

1. a property and default in `AppSettings`;
2. copy and normalization behavior in `AppSettingsService`;
3. UI load and save behavior;
4. tests for defaults, round-trip and invalid values;
5. schema-version consideration for migration.

Do not store passwords, Steam Guard codes or plaintext session tokens in settings files. Card Idler is the narrow exception for a refresh token protected with Windows DPAPI for the current user; clearing the saved login must remove that encrypted token.

## Native interop

Native Steam wrapper edits require special care:

- preserve x86 and x64 calling conventions;
- pass native object pointers exactly as required by the interface;
- verify callback packing and pointer alignment;
- keep native module lifetime explicit;
- include guards for unavailable interfaces and invalid handles;
- test both architectures before release.

Changes to SAM-derived files must retain the original copyright header and modification attribution required by the project license.
